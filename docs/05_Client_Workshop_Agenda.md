## 1. Purpose of the Workshop

Before development begins, the client must validate and sign off on:

1. The **business and functional scope** captured in the BRD/FRD.
2. The **operational behavior** the system should follow in real-world edge cases (Scenarios document).
3. Any **open questions** flagged during document preparation (e.g., Transport live-tracking, Library/Hostel modules, data retention policy).

This is a **decision-making workshop**, not a status update — every scenario walked through should end in one of three outcomes: **Confirmed**, **Needs Change**, or **Out of Scope (Phase 2 backlog)**.

---

## 2. Logistics

| Item | Detail |
| :--- | :--- |
| **Format** | 3 sessions (recommend 90 minutes each, same week or spread across 3 days) |
| **Mode** | On-site or video call, screen-share of live documents |
| **Pre-reads** | BRD, FRD, and Scenarios document sent 48 hours in advance |
| **Output** | Signed-off BRD/FRD + a decision log against every scenario |

---

## 3. Required Attendees

| Role | Why they're needed |
| :--- | :--- |
| School Admin / Trust Board Representative | Final authority on policy decisions (e.g., TC-hold-for-dues, refund policy) |
| Principal / Academic Head | Academic workflow validation (exams, report cards, timetable) |
| Accountant / Finance Head | Fee engine, concessions, refund, and reconciliation decisions |
| IT/Admin Coordinator (if available) | Data migration source format, existing systems in use |
| Vendor: Project Coordinator | Facilitates workshop, captures decisions |
| Vendor: Technical Lead | Answers feasibility questions in real time |

## 8. Post-Workshop Deliverables

1. Completed decision log, appended to the Scenarios document.
2. Updated BRD/FRD reflecting any **Needs Change** items.
3. Formal client sign-off (signature/email confirmation) on the finalized BRD/FRD.
4. Phase 2 backlog list for anything marked **Out of Scope**.
5. Green light to begin technical design and sprint planning.
